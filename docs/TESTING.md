# Правила тестирования

Контракт для агента (и человека): какие тесты пишем, где живут, как запускаем. Источник истины для правила AGENTS.md №9.

## Раннер

- **`bun test`** — встроенный раннер Bun, без отдельных зависимостей. Импорты: `import { describe, it, expect } from "bun:test"`.
- Тесты **co-located**: живут рядом с тестируемым файлом, имя `<module>.test.ts`. `bun test` рекурсивно находит все `*.test.ts` в проекте — отдельный корень `test/` не нужен.
- Гейты после написания теста: `bun test <файл>` зелёный, `bun run typecheck` и `bun run lint` чистые.

## Что тестируем

| Слой                                                                                                                    | Покрываем                                            | Как                                                                               |
| ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------- |
| Чистая логика `src/lib/**` (health, research, reviewAnalysis, aiLocales, storeLinks, metricColor, countries, withRetry) | обязательно при добавлении/изменении                 | обычные unit-тесты, без моков                                                     |
| `src/lib/appService.ts`                                                                                                 | бизнес-логику, где возможно                          | фейковые клиенты сторов / БД за интерфейсами                                      |
| `src/lib/stores/**`                                                                                                     | парсинг и маппинг ответов                            | фикстуры ответов API, без живых запросов                                          |
| Роуты и БД                                                                                                              | юнит-тестами **не** покрываем (нужен живой Postgres) | логику выноси в `src/lib/**` / `appService`, чтобы она была тестируемой без роута |

## Соглашения

- `describe('<Сущность>')` → `it('<поведение> when <условие>')`. Имена на английском — как весь код и комментарии в проекте.
- Фикстуры — рядом в `_fixtures/` или в самом файле, если маленькие.
- Живые сетевые вызовы в тестах запрещены — мокай `fetch`/клиенты.
- Одна тестируемая сущность — один файл теста (правило AGENTS.md №3).
